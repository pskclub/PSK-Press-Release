# วิธีโพสต์ (site recipes)

รายละเอียดของหน้าเว็บที่ระบบโพสต์อัตโนมัติใช้ เช่น ลิงก์หน้าอัปโหลด ช่องเลือกไฟล์
ช่องคำบรรยาย ปุ่มโพสต์ และชื่อปุ่ม "เพิ่มวิดีโอ" ของแต่ละเว็บ (TikTok / YouTube / Facebook)
เก็บเป็นข้อมูล (JSON) ไม่ใช่โค้ด — เมื่อเว็บเปลี่ยนหน้าตา แก้ไฟล์นี้แล้วผู้ใช้กด
**ตรวจหาอัปเดตวิธีโพสต์** ก็ได้ของใหม่ ไม่ต้องรอออกแอปเวอร์ชันใหม่

แอปรับไฟล์นี้เฉพาะเมื่อ **ลายเซ็น Ed25519 ถูกต้อง** (จากกุญแจของผู้พัฒนา)
และ **เลขรุ่นใหม่กว่า** ที่ใช้อยู่ ไฟล์ที่ผิดรูปแบบหรือลายเซ็นไม่ตรงจะไม่ถูกใช้
และส่วนขยายจะตรวจค่าทุกตัวซ้ำอีกครั้ง (ใช้ได้เฉพาะคีย์ที่มีในแบบที่มากับส่วนขยาย)

## ตั้งค่าครั้งแรก (ทำครั้งเดียว)

1. สร้างกุญแจ:
   ```
   node scripts/sign-site-recipes.mjs --init
   ```
   กุญแจส่วนตัวอยู่ที่ `~/.psk-press-recipes/private.pem` — **ห้ามใส่ใน repo** และสำรองไว้
   (ถ้าหาย ต้องออกแอปรุ่นใหม่ที่ใช้กุญแจใหม่)
2. นำ public key ที่สคริปต์พิมพ์ออกมาไปใส่ใน `src-tauri/src/site_recipes.rs`
   ที่ `PUBLIC_KEY_B64` แล้วออกแอปเวอร์ชันใหม่ (ก่อนหน้านั้นปุ่มอัปเดตวิธีโพสต์ยังใช้ไม่ได้
   และแอปใช้วิธีที่มากับส่วนขยาย)

## เมื่อเว็บเปลี่ยนหน้าตา

1. ใช้ **ตรวจความพร้อมการโพสต์** ในแอป (หน้าเชื่อมต่อ) ดูว่าขั้นไหนไม่ผ่าน
   แล้วกด **คัดลอกผลตรวจ** — จะได้ selector ที่ลองและ URL
2. แก้ `site-recipes/recipes.json` เฉพาะค่าที่เปลี่ยน แล้ว **เพิ่ม `version` ขึ้น 1**
   ถ้าต้องใช้ส่วนขยายรุ่นใหม่ ให้ตั้ง `minExtensionVersion`
3. ทดสอบกับเว็บจริงก่อน (`pnpm test:live` บนเครื่องผู้พัฒนา)
4. เซ็น:
   ```
   node scripts/sign-site-recipes.mjs
   ```
5. เผยแพร่ทั้ง `recipes.json` และ `recipes.json.sig` ไปที่
   `pskclub/PSK-Press-Release` โฟลเดอร์ `site-recipes/` (branch main)

## รูปแบบไฟล์

```json
{
  "format": "psk-press-site-recipes",
  "version": 2,
  "minExtensionVersion": "0.0.0",
  "sites": {
    "tiktok": { "postButton": "button[data-e2e=\"post_video_button\"]" }
  }
}
```

ใส่เฉพาะค่าที่ต่างจากแบบที่มากับส่วนขยายก็ได้ ค่าที่ไม่ใส่ใช้ของเดิม
คีย์ที่ใช้ได้ดูใน `extension/lib/recipes.js` (`BUILTIN_RECIPES`) — ค่าเป็นข้อความ
(selector หรือ URL แบบ https) หรือรายการข้อความ (ชื่อปุ่ม) เท่านั้น
